Storage and lifecycle behavior

Soft shutdown and reboot just send a request to guest OS and return immediately. Hard shutdown and reboot stop the guest instantly.

The demo uses a read-only EROFS base image and Linux is set up with a tmpfs overlay to capture writes. The system also support writable ext4 file systems that capture changes with a copy-on-write overlay. Reboots normally preserve the overlay but reset clears it for a clean restart.

The 9p file system also survives reboots normally, but the host can reset it while the guest is stopped. The host can also make arbitrary changes on the fly through individual file operations.

Boot output stays in terminal history on every boot, including reboot. Files in 9p and the HTTP disk overlay survive reboot until explicitly reset.

Copy to editor reads the selected file. Save to 9p replaces the copied file with the editor text. The file tree updates automatically; nothing saves automatically or checks for lost edits.

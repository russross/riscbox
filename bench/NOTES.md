Benchmark image preparation
===========================

`make` in this directory builds `build/rootfs.ext4`. Source changes in the guest scripts, benchmark C programs, vendored game source, builder, or boot asset-name files invalidate the image. Image construction is manual and never part of ordinary core checks or CI. Generated downloads, programs, boot files, logs, and images remain untracked.

The builder verifies SHA-256 hashes of the pinned Alpine 3.24.2 minirootfs and SQLite 3.50.4 source archives. It extracts SQLite's amalgamation and speedtest1 program, then cross-compiles static RV64GC/lp64d loop and SQLite executables at `-O2`. SQLite uses memory-only temporary storage, no worker threading, and no extension loading. Compiler identity and flags are recorded in `build/toolchain.txt`. Only source, headers, Makefiles, licenses, and Markdown from the five vendored games enter the guest fixture.

The kernel and OpenSBI files named by their asset-name files are decompressed into build storage. Fakeroot combines the Alpine root with the benchmark guest scripts into a gzip-compressed newc initramfs while preserving ownership. Unique temporary directories hold the initial root and guest output. Exit cleanup removes both directories and `build/rootfs.ext4.part`; HUP, INT, and TERM exit with failure rather than continuing construction.

QEMU boots one RV64 hart with 512 MiB RAM, OpenSBI, the canonical Linux kernel, and the setup initramfs. Linux runs `/sbin/bench-prepare` directly, with UART output and legacy ISA fallback. QEMU provides user networking for package installation and two VirtIO 9p shares: the read-only benchmark directory and a writable temporary output directory. It has no monitor and reads stdin from `/dev/null`; serial output and host diagnostics go to `build/image-setup.log`. A ten-minute timeout requests termination. Timeout or interruption escalates to SIGKILL after five seconds if QEMU does not exit.

The preparation guest mounts proc, sysfs, devtmpfs, and both shares, configures DHCP, and installs musl development files, TinyCC, its static libraries, make, and ncurses development files. It copies the cross-compiled programs and game sources into `/bench`, builds every game serially with TinyCC, and cleans the game outputs. It verifies the loop's known 1000-iteration checksum and runs SQLite's main verification workload at size one in memory. Any preparation error writes an output failure marker and requests poweroff.

After validation, the guest records sorted package versions, removes its preparation script and package caches, and exports the root to `rootfs.tar` on the output share with numeric ownership retained. Device, proc, sysfs, temporary, run, and mount contents are excluded. Only a successful tar export permits the completion marker. The guest disables the failure trap, synchronizes filesystems, and powers off. The host requires successful QEMU exit, a completion marker, and no failure marker before consuming the archive. Failures report the log path and its last twenty lines.

Fakeroot extracts the exported root and populates a new 96 MiB ext4 image with no reserved block percentage. The package list is copied to `build/packages.txt`. A rename from `rootfs.ext4.part` to `rootfs.ext4` publishes the completed image only after filesystem creation succeeds. Script cleanup retains downloads, compiled programs, logs, and any previously completed image; Make's `.DELETE_ON_ERROR` policy still applies to its target when a recipe fails.
